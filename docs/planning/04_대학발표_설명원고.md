# 여정 — 기획 발표 설명 메모

작성일: 2026-11-01 · 7장 · 발표 시간 미정 · 앱 실시간 시연 없음

최종 자료는 [여정 기획 발표 수정본](../../presentation/여정_기획발표_수정본.pptx)이다. 이 문서는 별도 설명 자료이며 **PPTX의 발표자 노트·댓글·노트 파트는 모두 제거했다.**

## 1장 · 표지

“여정은 일정과 예약서 등 흩어진 여행 정보를 한 여행 안에서 확인하는 개인 여행 관리 앱입니다.” 표지의 라임 경로 아이콘과 로딩폰은 생성한 디자인 콘셉트이며 실제 시작 기능의 실행 증거는 아니다.

## 2장 · 목차

“앱 소개와 장점, 실제 화면의 사용 흐름을 먼저 설명하고 기술 스택과 전체 시스템 구조, 다음 계획을 소개하겠습니다.”

## 3장 · 앱 소개와 장점

“계획부터 기록까지, 한 여행 안에서 관리합니다. 여행 정보를 모아 찾고, 남은 준비와 날짜별 계획을 확인하도록 구성했습니다.”

## 4장 · 핵심 사용 흐름

“국가별 도시·지역 검색으로 목적지를 고르고, 홈에서 여행 정보와 준비 상태를 봅니다. 일정에서는 날짜와 현지 시각에 따라 장소·메모를 확인합니다.”

실제 앱 캡처는 [목적지](../../presentation/assets/destination-screen.png) → [홈](../../presentation/assets/home-screen.png) → [일정](../../presentation/assets/flow-screen.png) 순서다. Simulator의 Save Screen으로 디스플레이만 내보냈으며 폰 외곽선은 PPT 도형이다.

## 5장 · 기술 스택

“핵심 선택은 Kotlin 하나로 Android·iOS 앱과 서버를 개발하는 것입니다. KMP·Compose로 공통 로직과 화면을, Ktor Client와 Spring Boot로 앱 통신과 서버 API를 구성합니다.”

‘Kotlin 하나로’는 언어 중심의 통일을 뜻한다. 앱과 서버 전체가 동일 코드로 자동 동작하거나 플랫폼별 구현이 사라진다는 뜻은 아니다. Flutter·React Native 등 대안보다 성능이 우수하다는 실측 주장은 하지 않는다.

## 6장 · 전체 시스템 구조

“현재 앱은 Ktor Client를 거쳐 자체 REST API에 요청하고, 로컬 서버는 JSON과 파일을 저장합니다. PostgreSQL·인증·동기화와 외부 API 연동은 후속 구성으로 구분했습니다.”

국가·도시는 로컬 목록에서 검색한다. 현재 Google 항공편·지도는 외부 화면 이동이며 항공·숙소 공급사 API는 선정 전이다.

## 7장 · 현재 범위와 다음 단계

“현재는 여행·일정·준비물·수동 예약·서류·경비·장소·기록의 핵심 흐름을 구체화했습니다. 정보 찾기와 입력 흐름을 검증한 뒤 로그인·DB·동기화와 외부 연동을 검토할 계획입니다.”

## 사실 확인 기준

- 만든 목적은 정보 분산 문제 해결이다. 확인되지 않은 개인 경험·시장 통계·개선 수치를 덧붙이지 않는다.
- 캡처의 여행·예약을 실제 공급사 예약·발권·가격 확인 결과로 설명하지 않는다.
- 현재 저장은 로컬 JSON이며 PostgreSQL은 후속 목표다. 실시간 운임·내부 예약·결제·자동 동기화 완료를 주장하지 않는다.
- 파일·오프라인 조회와 플랫폼별 확인 범위는 [검증 기록](../VERIFICATION.md)을 따른다. 조회와 오프라인 편집을 구분한다.
