# 여정 — 기획 발표자 메모

작성일: 2026-11-01 · 발표 시간 미정 · 앱 실시간 시연 없음

[핵심 발표 구성](06_기획발표_핵심구성.md)을 설명하는 장별 메모다. 앱 화면은 **국가별 목적지 38 → 홈 01 → 일정 02**의 실제 캡처 3장을 반드시 포함한다. 본문에는 짧은 핵심 문장과 화면·구조도를 배치하고, 아래 설명과 검증 주의사항은 발표자 메모로 둔다. [디자인 가이드](07_발표자료_디자인가이드.md)를 함께 참고한다.

## 1장 · 왜 만드는가

“일정은 메모에, 예약서는 이메일에, 장소는 지도에 나뉘어 있으면 필요한 정보를 다시 찾아야 합니다. ‘여정’은 여행을 직접 준비하는 개인이 이 정보를 한 여행 아래에서 확인하도록 기획했습니다. 여행 중 자주 확인하는 흐름이므로 휴대전화 앱을 중심으로 구성했습니다.”

## 2장 · 무엇을 하는 앱인가

“첫 화면은 일본을 선택한 뒤 해당 국가의 도시·지역을 찾는 모습이고, 홈은 선택한 여행과 준비 상태를 모아 보여줍니다. 일정 화면에서는 날짜와 현지 시각에 따라 장소·메모를 확인합니다. 여기에 준비물, 수동 예약·서류, 경비, 장소와 기록을 같은 여행에 연결했습니다.”

화면 용도는 [국가별 목적지](../screenshots/38-country-places.png)에서 여행을 시작하고, [홈](../screenshots/01-home.png)에서 전체를 확인하며, [일정](../screenshots/02-schedule.png)에서 필요한 계획을 찾는 흐름이다. 앱을 조작하는 대신 이 캡처를 설명한다.

## 3장 · 시스템은 어떻게 연결되는가

“현재 앱은 공통 Kotlin 화면·상태 로직에서 Ktor Client를 거쳐 Spring Boot의 REST API로 요청하고, 로컬 서버는 JSON과 첨부파일을 저장합니다. 국가·도시 검색은 로컬 목록을 사용하며 Google 항공편·지도는 외부 화면으로 이동합니다. PostgreSQL·인증·동기화는 후속 목표이고 항공·숙소·환율 등 외부 API의 구체적인 선정은 아직 미정입니다.”

[전체 시스템 구조 PNG](assets/system-architecture.png) · [SVG 원본](assets/system-architecture.svg)의 현재·후속 구분을 따라 설명한다. 외부 화면 이동을 실시간 데이터 API 연동으로 표현하지 않는다.

## 4장 · 왜 이 기술을 선택했는가

“KMP와 Compose는 Kotlin 중심으로 두 모바일 플랫폼의 공통 로직과 화면을 유지하려는 선택입니다. Flutter와 React Native도 비교했지만 이번 프로젝트의 개발 방향과 공통 화면 비중을 기준으로 판단했습니다. 통신은 Ktor Client, 서버는 Kotlin·Spring Boot이며 현재 JSON 저장을 후속 PostgreSQL 전환과 구분합니다.”

## 5장 · 지금과 다음 단계

“현재는 기획 발표 단계로 핵심 기능과 화면, 시스템 구조를 구체화했습니다. 이후 사용자가 일정과 예약 정보를 쉽게 찾는지 확인하고 개선할 계획입니다. 로그인·운영 DB·여러 기기 동기화와 실제 예약·결제는 후속 개발입니다.”

## 자료 해석·질문 대응 메모

- 만든 계기는 정보 분산 문제를 해결하려는 기획 목적이다. 확인되지 않은 개인 경험·인터뷰·시장 통계나 경쟁 우위를 덧붙이지 않는다. 정보 찾기 시간 감소는 향후 검증할 가설이다.
- 캡처의 여행·예약은 화면 흐름을 설명하는 자료다. 실제 공급사 예약·발권·가격 확인 결과로 소개하지 않는다. 국가 선택 화면을 실시간 관광 추천으로 설명하지 않는다.
- 파일 업로드·네이티브 열기·재시작 후 오프라인 조회는 각각 최신 [검증 기록](../VERIFICATION.md)에 근거가 있을 때만 완료라고 설명한다. 파일 조회를 오프라인 편집·자동 동기화로 확대하지 않는다.
- 현재 DB 질문에는 “로컬 JSON 저장, PostgreSQL은 후속 목표”로 답한다. 앱 자체의 실시간 운임·예약·결제 기능은 없으며 외부 API 선정도 미정이다.
- Android·iOS 빌드와 실제 화면별 확인 범위를 구분한다. 공개 배포 완료나 모든 기기 검증을 주장하지 않는다. 실측하지 않은 프레임워크 성능·개발 속도 배수와 최신 테스트 개수를 원고에 고정하지 않는다.

전체 장기 요구사항은 [PRD](01_기획_PRD.md), 기술 비교 근거는 [기술 선택 문서](03_기술스택_선정과_비교.md)에 있다. 해당 문서의 장기 아키텍처를 현재 구현으로 설명하지 않는다. 이 단계에서는 PPTX를 생성하지 않는다.
