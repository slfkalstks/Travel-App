# 개인 여행 공간 — 앱 전환 기획 문서 v2.0

작성일: 2026-11-01 · 문서 상태: 검토 가능한 설계 초안 · 작성 언어: 한국어

**여행을 준비하고, 여행 중 필요한 정보를 꺼내 보고, 여행 후 기록을 남기는 개인 전용 Android·iOS 앱**을 만든다. Kotlin Multiplatform으로 공통 로직을, Compose Multiplatform으로 공통 화면을 작성하고 Kotlin + Spring Boot 서버와 PostgreSQL을 연결한다.

이 문서는 사용자의 앱 전환 요청에 맞춰 기획·PRD·설계를 새로 작성한 기준 문서다. 구현 완료 보고서가 아니다. 기존 프로젝트를 조사했지만 소스코드·DB·기존 문서는 변경하지 않았다. PPTX도 생성하지 않았다.

## 문서 구성

1. [기획 및 PRD](01_기획_PRD.md): 누구의 어떤 문제를 해결하는지, 전체 기능, 사용자 흐름, 인수 조건, 개발 단계.
2. [시스템 및 데이터 설계](02_시스템_데이터_API_설계.md): 앱·서버 구조, ERD, API, 오프라인 동기화, 인증, 파일·알림·외부 연동, 전환 계획.
3. [기술 스택 선정 및 비교](03_기술스택_선정과_비교.md): 기술별 선택 이유, 대안, 단점, 재검토 조건, 공식 출처.
4. [대학 발표용 설명 원고](04_대학발표_설명원고.md): 발표 흐름, 기술 개념 설명, 시연 계획, 예상 질문.

## 결정의 출처

| 구분 | 내용 |
|---|---|
| 이번에 사용자가 확정한 내용 | 여행 프로젝트를 앱 중심으로 전환, Kotlin Multiplatform 사용, 기획·설계·PRD부터 재작성, 부족한 부분 보완, 기술별 비교 설명, PPTX는 요청 전까지 만들지 않음 |
| 기존 요구사항에서 유지 | 개인 전용, 한국어, Spring 백엔드, 앱·서버·DB 분리, 여행 전 과정, 국내 카카오맵·해외 Google Maps, 토스뱅크 환율 목표, 내부 예약·결제·취소 목표 |
| 이번 문서의 설계 제안 | Android·iOS 동시 목표, Compose 공통 UI, Room 로컬 저장, 모바일 토큰 인증, 오프라인 편집 및 충돌 처리, 단계별 구현, 수동 DI, 서버 단일 배포 |
| 아직 확정할 수 없는 사항 | 발표일·발표시간·평가기준, 실제 개발 인원과 가용 시간, 배포 예산, 실제 테스트 기기, 외부 API 계약 및 키, 앱스토어 공개 여부 |

미확정 사항 때문에 문서 작성을 멈추지 않고 기본 제안을 명시했다. 개발 일정은 날짜 약속 대신 검증 가능한 단계로 작성했다. 최초 사용자 범위는 기존 요구에 따라 소유자 한 명이고 여러 기기에서 사용할 수 있다. 공개 회원가입과 동행자 협업은 별도 확장 제안이다.

## 기존 웹과 달라지는 부분

| 기존 | 새 기준 |
|---|---|
| React + TypeScript 웹/PWA | KMP + Compose Android·iOS 앱 |
| 브라우저 세션 쿠키·CSRF | 모바일 Bearer 토큰·기기별 세션, 웹 인증은 별도 유지 가능 |
| 명시적 오프라인 스냅샷 | 로컬 DB 기반 조회·편집, 재연결 동기화 |
| 웹 지도·파일 API | Android/iOS 네이티브 지도·파일·알림 어댑터 |
| 서버 전체 workspace 조회 | 여행별 조회·페이지네이션·변경분 동기화 |
| JSON 숫자 금액 | v2 API의 십진 문자열 금액, 서버 정밀 계산 |
| 웹용 기능 테스트 | 공통 로직 + Android/iOS 실기기 검증 |

## 근거와 현재 상태

기존 `docs/PRODUCT.md`, `docs/API.md`, `docs/PROGRESS.md`를 확인했다. 이 문서들에는 웹 관리 기능과 PostgreSQL 연동 검증 기록이 있고, 외부 공급사 연동은 별도 과제로 기록되어 있다. 이번 작업에서 과거 테스트를 재실행하거나 새 앱을 빌드하지 않았다. 따라서 기존 테스트 숫자를 앱의 성과로 사용하지 않는다.

외부 기술 정보는 2026-11-01 확인한 공식 문서에 근거한다. 문서 03의 출처를 함께 읽으면 된다. 기술의 지원 사실과 이 프로젝트에 적합하다는 설계 판단은 구분했다.
