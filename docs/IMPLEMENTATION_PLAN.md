# 모바일 구현 범위 및 검증 계획

2026-11-01 사용자 피드백에 따라 기존 UI를 전부 교체했다. 제품 대상은 Android와 iOS이다. 현재 우선순위는 대학 기획 발표이며, 실제 화면을 넣고 실시간 앱 시연은 하지 않는다. 운영 기능 추가는 후속 백로그로 보류한다.

## 이번 구현

- 다중 여행: 목록·선택·이름/목적지/국가 검색·보관 필터, 생성·7필드 수정·보관/해제·영향 확인 후 삭제, 여행이 없는 상태의 생성 안내
- 목적지 선택: 국가 검색·선택 후 국가별 도시/지역 검색, 국가 변경 시 도시 초기화, 오프라인 지명과 직접 입력 경로
- 여행별 데이터: 앱의 하위 요청에 `X-Trip-Id` 전달, 서버의 요청별 선택과 데이터·멱등성 영수증 격리, 새 여행의 빈 일정·준비물·경비·예약·장소·기록
- 기존 저장 파일: 원본 바이트 백업 후 schema 2 여행 컬렉션으로 이전, 기존 자료·멱등성 영수증 보존, 마지막 여행 삭제 후 재시작에도 빈 목록 유지
- 공통 Compose UI: 여행, 항공권, 장소, 기록, 설정
- 여행 상세: 일정, 준비물, 예약, 경비
- 예약 기록: 종류별 생성·전체 수정·반복 삭제, 시각 미정·시간대 검색·DST 선택, 체크아웃·취소 마감·규정 메모, 계약 스키마와 생성 DTO
- 일정: 추가, 날짜·시간·제목·분류·장소·메모 전체 수정, 메모만 수정, 일정명·날짜를 확인한 뒤 삭제
- 준비 항목: 추가·이름/분류 수정·삭제 확인·완료 체크. 수정 시 기존 완료 여부 보존
- 기타 저장: 지출·메모 추가, 장소 저장
- 일정의 예상 비용·좌표는 전체 수정 요청에서 제외하고 서버의 기존 값 보존
- 상세에서 작성 중인 메모는 저장 성공 후 전체 수정 화면으로 이동; 실패하면 입력 유지
- 외부 연결: 노선·날짜를 반영한 Google 항공편 검색, 장소별 Google 지도
- 날짜·시간·금액 검증, 필드별 오류, 실패 시 입력 유지, 재시도 중복 생성 방지
- 밝은 화면과 어두운 화면, 동작 줄이기
- 여행 서류: 네이티브 선택·업로드, 예약 연결·이름 수정, 다운로드·해시 검증 캐시·삭제 계약
- 기기 보관: 여행 조회 스냅샷·읽기 전용 오프라인 상태·캐시 복구. 오프라인 편집·자동 동기화는 미구현

일정·준비물·여행·예약 관리는 프런트엔드 화면·입력·확인 흐름을 먼저 구성한 다음 서버 저장 기능에 연결했다. 다른 도시의 홈과 항공 검색은 선택한 여행에 맞춰 표시하며, 목적지 공항을 찾지 못하면 직접 선택을 요구한다. 최신 API·공통 상태 테스트, 기존 데이터 보존 및 실제 모바일 검수 범위는 [검증 기록](VERIFICATION.md)에 정리했다. [현재 다중 여행 계약](MULTITRIP_API.md)은 향후 인증·동기화용 API v2 설계와 구분한다.
